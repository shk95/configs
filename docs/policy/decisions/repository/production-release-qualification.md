date: 2026-10-01
scope: repository
status: accepted
reopen-when: A public contract, supported platform or executing tool identity changes.

## Decision

Keep ordinary bounded preview inputs available. Explicit production mode inventories
the complete candidate Git tree using the existing classifier's per-path records.
Reviewed exact path mappings include master-to-dev migration history; historical
roots cannot become live candidate configuration authority. Unknown ownership,
unmapped paths, foreign check ownership, absent or non-regular public surfaces and
declared defects refuse. A future source path requires reviewed mapping, not a
whole-domain fallback. The source tree never supplies executable preview code.

Pin constructor, inspection, capture and Windows generation/consumer surfaces by
Git blob, and pin declared tools to exact versions and relevant source blobs. Each
proposed domain release requires that domain's complete public contract evidence,
including native representative platforms. Linux evaluation, native build, Windows
runtime and bootstrap checks remain distinct; hosted Windows proof cannot stand in
for the declared LTSC baseline. Private fleet outputs remain consumer-owned.

A bootstrap proposal lists immutable identities and obligations but is UNSELECTED.
Actual initial unixlike-v1.0.0 and windows-v1.0.0 adoption requires maintainer review,
a separate source-bound record and genuine evidence. Existing calendar annotations
are immutable and cannot become semantic baselines implicitly. After explicit
cutover, structured cumulative impact, compatibility, migration and exact inverse
revert comparison apply only to this optional qualification input contract.

Affected Unix-like API release requires an already delivered adaptation revision
in shk95/configs-host-template and verification of that exact provider/template
pair. Updating the template's provider release pin happens independently after
release; a future pin is not required before its release exists.

Offline verified receipts remain assertions. Even an accepted production-mode
preview reports production_certification=false; authenticated provenance and actual
release mutations belong to separately reviewed operating transport. This decision
adds no live transport to release-controller-preview-boundary.md and does not
change activation, Apply, promotion, tag or credential authorization.
