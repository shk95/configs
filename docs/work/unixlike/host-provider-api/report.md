## Evidence lanes

- Evaluation: `provider-api-test` passes across a separate consumer flake for all three constructors and checks negative cases; all seven current output derivation paths match the clean `e8730ce` baseline. `nix flake check --no-build`, `composition-test`, and `import-order-test` pass on aarch64 Darwin. The existing local `flake-test` passed its schema fixtures, while its later installation fixture stopped because macOS `/var` is a symlink. The first Linux CI run found that the graphical runtime fixture, which composes classes without a constructor, lacked typed Home Manager identity. After that fixture supplied it, CI runs `35975584104` and final `35977694175` passed `flake-test`, full output evaluation, and `import-order-test` on x86_64 Linux.
- External template evaluation: Public template commit `dcb8c6d` pins the provider merge and passed `tool/check-hosts` locally and in Linux CI run `35979339688`; the repository is marked as a GitHub template.
- Build: The existing Darwin output built natively on aarch64 macOS after the API refactor. CI run `35975584104` built the standalone x86_64 Linux home. The private consumer's Darwin output built natively on aarch64 macOS. Its OrbStack output built on the already running aarch64 Linux machine with `nix build --no-link --max-jobs 2`; the resulting system path differed from `/run/current-system`. The UTM consumer also built its toplevel with that command inside its aarch64 NixOS guest, first in disposable mode. That test temporarily used macOS Shared Network to fetch inputs, then restored the original VM configuration byte-for-byte. After the maintainer authorized Shared as the permanent VM mode, a fresh guest boot showed a default route and successful DNS lookup. In a later non-disposable boot, the reviewed consumer flake and lock were copied into the guest with matching hashes and built natively again. The candidate differed from the preceding running system path; `nix store diff-closures` showed no package difference. After the build, `/` had 32 GiB free and `/boot` had 866 MiB free, with both generations retained. The other installed Linux and WSL consumers still need matching builds.
- Native runtime: The isolated OrbStack machine remained reachable after consumer test activation and after the later restart. On the restarted machine, its running, booted and boot-profile system links all matched the consumer candidate; `systemctl is-system-running` returned `running`, Home Manager was active, DNS worked, and no units had failed. Isolation stayed enabled, `systemd-binfmt` stayed runtime-masked, and `binfmt_misc` stayed unmounted. In UTM, key-authenticated SSH worked after test activation and again after reboot. The rebooted guest's running, booted and boot-profile system links all matched the consumer candidate; the system was `running`, sshd, greetd and Home Manager were active, DNS and the default route worked, and no units had failed. The hypervisor console displayed Niri and Noctalia after test activation. The maintainer directly confirmed Ghostty, WezTerm, Noctalia launcher and control centre, Korean input and audible playback after test activation and again after reboot. These graphical and audio observations are maintainer-confirmed, distinct from the agent's service checks. Other installed consumers still need independent runtime evidence. The physical desktop has no installed runtime.
- Activation: The maintainer explicitly authorized an OrbStack test activation on 2026-09-24; `nixos-rebuild test` succeeded while the boot profile retained the preceding generation. After separate authorization, `nixos-rebuild switch` succeeded and `orb restart orbstack` booted the consumer candidate. The preceding generation remains available for recovery; no rollback was needed. The maintainer authorized the UTM activation and recovery procedure. Its `nixos-rebuild test` succeeded while the boot profile retained the preceding generation. `nixos-rebuild switch` succeeded, followed by a guest reboot into the candidate. `nixos-rebuild switch --rollback` then selected the preceding generation for the running system and boot profile while SSH, greetd and Home Manager stayed active; a final consumer switch restored the candidate. No garbage collection was run. No other consumer activation was requested.
- Review: The typed public arguments and extension points are recorded in `docs/policy/decisions/unixlike/provider-constructors-own-composition.md`. The public template and private consumer declarations are available. Host-specific native evidence, secret recipients and final provider-only state remain pending; the current provider inventory and outputs stay in place.
