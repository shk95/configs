## Wrapper contract

Use a dedicated single-job writer run and fixed job-level concurrency with
cancel-in-progress=false. Inspector/wait executions are independent and receive
no writer PAT or private connection. Serialize operator reruns; Actions pending
concurrency is not a durable FIFO. Identify the actual current job through complete
API observations, never through request-supplied identities or an assumed job ID.

The entry executes the approved immutable source and its verified transport
inventory, never candidate code/artifacts/caches. Separate credential-free candidate
refresh and validation from trusted publication; independently validate lock-only
changes and complete PR history. Use the original retained package to create,
claim, plan and project events; durable intent precedes every external write.
History/config/control identity transitions require explicit compatibility checks.

Keep approved public master, semantic control and actual owner run source distinct.
An outstanding batch retains pinned configuration and approval obligations; a fresh
stop and credential revocation remain live. Candidate changes invalidate approval.
Unknown acknowledgements fence further writes until observations reconcile them.
Cancellation is only the recorded sole owner job/run and requires terminal proof.

authorized actor IDs, Environment, writer workflow/path/job, deployed master,
transport inventory, semantic package, source-bound bootstrap and complete domain
evidence. Unresolved fields refuse. No token goes in Git, arguments or logs.

The concrete credential/setup inventory is study.md. Endpoint-specific allowed and
denied observations must follow actual deployment. Existing Required checks,
administrator/conversation enforcement and no-force/no-deletion protections remain
unchanged; unsupported stronger review policies return to planning. Source promotion
and immutable domain tags obey their accepted governance and evidence contract;
semantic bootstrap/tag adoption requires reviewed source-bound acceptance first.

## Verification and stop conditions

Fake transport plus disposable real Git covers no-op/failure, old-package recovery,
conflicting records, lost response, invalid runtime/attempt, mixed-job cancellation,
stale checks/base/approval, partial tag publication and changed candidate inputs.
Actual deployment separately proves rejected foreign refs/candidate secrets,
endpoint permissions, source/protection/evidence authenticity and user notification.
Retain receipts without private values in public summaries.

Stop/replan for new endpoints/protocols, wider token access, candidate execution in
privileged control, unavailable domain/native evidence, bootstrap ambiguity,
unexpected merged parents/tree, record conflict, uncertain owner termination,
incompatible retained history or a competing continuation owner. Do not bypass a
gate, silently migrate old batches or restore a retired publisher.
