## Outcome and ownership

Implement the missing repository transport boundary between the delivered inert
controller and an explicitly provisioned operating connection. Root owns sequential
planning/continuation. Source pickup waits for global-history, caller retirement and
reviewed production qualification delivery; pin reviewed plan and current dev in a
dedicated worktree and assign an execution issue before implementation.

## Inputs and trust decisions

Use provider-release-contract/spec.md's master-only trusted loader, retained approved
semantic closure, single outstanding batch, pinned config and fresh stop, record-before-
mutation/reconciliation, exact candidate approval and timeout/recovery requirements.
The preview-boundary decision must be reconsidered through governance review before
introducing live effects. There is no permission hidden in a new mode flag.

The maintainer supplies the actual private operating repository/ref, approved public
control/master/bootstrap identities, connection and Environment names, exact actor/
workflow identities and intended permission scopes. Secret values stay in the
approved secret store and never in plans, records, arguments or logs. The existing
preview workflow is not installed on current master and does not execute controller
source; production wiring needs separately reviewed source promotion and provisioning.
Do not choose an arbitrary private repository or reuse configs-hosts as operating
storage by similarity. Missing inputs block live wiring, not fake source verification.

Read actual authenticated GitHub workflow/run/job/ref/event/actor and check/protection
observations independently of request bodies and candidate artifacts. Bind receipts
and exact head/base/merge tree/tool/source identities. Reject wrong master entry,
mutable assertions, stale checks, incomplete lookup/pagination and ambiguous authority.
Retained code executes only manifest-verified approved blobs with isolated environment;
configuration is data. A PAT allowlist alone does not prove ref/Environment isolation.

## Effects, records and recovery

Implement an injectable finite transport, with fake endpoints for deterministic
source proof. A live adapter is explicitly selected only in a separately approved
master/Environment context; preview defaults remain inert. Append immutable intent
before each operation and reconcile its authenticated result. Read/write operating
records with reviewed Git ancestry and expected-head non-force update; competing
writers or unknown acknowledgement fence further effects. Generation is not API CAS.

Implement exact batch-owned refresh branch creation/normal update and fresh complete
PR lookup/join/confirmed absence/unknown refusal. A new pending PR count is not a
lookup receipt. Keep feature-to-dev refresh and dev-to-master promotion distinct.
Check exact current checks/protection/base immediately before merge; API head guard
is not expected-base CAS. After promotion, verify actual parents/tree/source before
any publication. Tag object/ref payloads are fixed and immutable, duplicate success
joins, conflicts stop, unknown operations reconcile before candidate advance.

Requests, wakeup, stop/resume/approval authentication, timeout/termination, cancellation
of the exact owned job and notification receipts use explicit finite schemas. Never
cancel a foreign job or start a second batch while an old effect is unknown. Do not
repair missing provenance by importing an untrusted artifact. Complete prior history
and immutable configuration/package remain independently verified. Preserve bounded
public output without private connection or raw record payloads.

## Delivery and operating gates

One coherent repository source PR carries reviewed trust/transport/writer interfaces,
workflow changes left disabled, fake positive/refusal/failure/recovery fixtures,
Linux/native Git-for-Windows proof, operator recovery documentation and this report.
Use an explicit disposable fixture environment; no fake test contacts production.
A tested adapter is not a manual operating proof. No actual ref/tag/promotion/cancel/
workflow dispatch, operating repository creation, secret/Environment/protection mutation,
notification delivery, enablement, host activation or Apply is assigned by source pickup.

After source integration, prepare a concrete R-manual run proposal naming actual
inputs, permissions and expected effects for approval. Complete the manual report
with authenticated receipts before separately enabling scheduled 05:00 refresh,
06:00 promotion and 07:00 cutoff (Asia/Seoul), including missed/late/retry recovery.
Replan on changed trust model, missing actual identity/protection, closure expansion,
unsupported protocol or inability to reconcile a write conclusively.
