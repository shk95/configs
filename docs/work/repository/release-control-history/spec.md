## Selection and replay design

Consume a complete supplied local operating Git snapshot at an exact accepted
head, with the fixed config/stop/history/index paths. Verify regular-file modes,
original UTF-8 bytes, global filenames/sequences and prior-event digest chain.
Never renumber, normalize or re-encode retained events. Validate every completed
prefix through that batch's exact verified old semantic package and pinned config;
a structural completion marker alone proves neither completion nor indexing.
Reject overlapping outstanding batches, gaps, missing dependencies or ambiguous
boundaries. Reconstruct the global index from semantic results, binding the entire
ledger anchor and the selected batch projection rather than trusting the index.

For the outstanding suffix, select recorded full approved master/control identities,
manifest blob identity and digest, approval-provenance identity and supported
loader/record/replay protocol. Select recorded config commit and blob identity at
literal config/operating.tsv, prove the commit reachable through accepted operating
history and read immutable bytes from that object. Content identity and reachability
are required but are not authentication. Missing binding refuses; do not infer an
approved source from any ancestor or from a current caller-supplied assertion.
The exact encoding of additional bindings awaits the compatibility amendment.

Extract the full selected semantic package from the fixed public repository/root
into isolated scratch after checking exact source identity, approved-merge shape,
reachability, manifest and every executing dependency. Current-loader glue verifies
framing and selects a supported interface; retained code owns stage, approval,
completion and projection meaning. Never mix old engine with current rules,
adapters or classifier. Never execute candidate code, arbitrary paths or URLs.
Git reads disable replacement objects, lazy fetch, external protocols and ambient
execution overrides; unavailable/shallow history refuses without network recovery.

Immutable batch config governs recovery even after current config edits. Current
config/approved context governs only a no-outstanding or later new-batch selection.
Read global live stop separately from the fresh accepted head, never from the pinned
batch config. This preview selects and reconstructs; it does not create batches,
write operating records or perform remote operations. No-outstanding may produce a
bounded quiet selection result, without inventing approval or an operational action.
