## Assignment and dependencies

Root owns this design child under #479/manual-source-continuation. Reviewers
prepare read-only analysis; root serializes shared transport source. Observed
candidate source and production-map closure are prerequisites for implementation,
not production receipt authority. Coordinate generated Release-* custody and
next-protocol changes with release-refresh-object-compatibility.

## Required design result

Classify selected requirements by actual producer: independently observed Actions
check, authorized domain review, representative native execution or delivered exact
template/provider pair. Workflow success and supplied verified rows do not prove
all four. Define bounded typed packets binding original dev/master/merge objects,
control/rules/package/manifest, baseline bytes/digest, selected IDs and tools,
source blobs, evidence lanes and raw original receipts. Native records identify
platform, execution source, command/tool and result; template records identify
original adaptation revision and exact delivered provider pairing.

Matching packet hashes are assertions, not independent review. Keep private packet
and raw native material out of public source, inputs, logs, artifacts and chat.
Specify trusted acquisition without inventing an issuer. Project original evidence
TSV/template rows only from validated typed receipts, with exact selected coverage.
Missing, duplicate, foreign, malformed, changing or unsupported receipts refuse.
Reobserve custody and source around projection and journal publication; source,
baseline, rules, tools, selected obligations or pair changes invalidate review.
Routine review custody, exceptional candidate promotion approval, bootstrap adoption
and generated Release-* judgement remain distinct authorities.

## Review-only GitHub custody proposal

Evaluate a separate accepted-master, manual-only sole-job workflow receiving only
canonical packet_digest. Original run-name binds its display title. Proposed job
permissions are empty, with no checkout, credential, private locator, packet bytes,
artifacts, operating writes or approval effects. Account explicitly for any
platform-created deployment metadata. A separate review Environment would hold for actual authorized
human review; root/source implements no approval POST or automatic issuer.

Evaluate independent original workflow/source, repository, event/ref/run,
latest attempt=1, sole successful job, exact title, authorized reviewer numeric ID
and Environment numeric ID. Verify private packet bytes/hash/bindings independently.
Consider an explicit digest in the approval comment as acknowledgement.

Review history is run-scoped: it supplies no approval timestamp, job ID, attempt or
dispatch input bytes. Environment timestamps are not approval timestamps; current
settings do not prove historical protection. Determine whether source-derived title,
sole-job topology and actual review suffice for the narrow adopted claim. Resolve
title mutation/input observation and actual hold ordering limits or refuse pickup.
Reject reruns, unavailable/deleted observations and mixed or ambiguous histories.
One-of-required-reviewers does not prove multiple independent domain approvals.
No proposed Environment, role, endpoint, reviewer policy or permission is adopted
by this plan. Compare alternatives before choosing the custody contract.

## Representation, pickup and operating gates

Decide exact original evidence/transcript projection versus next-protocol custody
events, revocation/recovery and fields. Preserve old packages, operation IDs,
reducers and historical replay; do not add unknown old transcript keys. Specify
loader/inventory/dispatch compatibility and proposed fixed GET endpoint grammar,
origins, bounds, completeness, repetition and refusal. No implicit artifact/log
download, template credential expansion, approval POST or fallback.

The design report must name durable decisions/invariants and ordered same-scope
source increments with positive/negative fixtures. Source pickup follows accepted
design; this child deploys no proposed workflow or receipt mechanism. Actual
operator gates remain semantic bootstrap adoption, domain declaration judgement,
genuine native records, delivered template pairing, independent packet review and
reviewer authority, Environment hold/ref/secret isolation and permissions. Approved
native assertions are not GitHub-verified execution. Initializer certificates do
not become production review authority. Accepted exact receipt reuse may avoid a
human hold on every routine writer, while preserving live stop and batch obligations.

Stop/replan for missing authority, original evidence, receipt scope, reviewer
coverage, representability or observable custody. No private writes, Environment
configuration, dispatch, issuer, promotion, initializer, release, schedule,
activation, Apply or cleanup is assigned.
