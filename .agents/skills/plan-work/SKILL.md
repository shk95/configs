# plan work

Read AGENTS.md, CONTRIBUTING.md, docs/work/README.md and the owning scope's
current state. Inspect the generated work index and relevant existing work
before creating a duplicate plan. Historical reports are evidence, not rules.

For small unambiguous work, state the outcome and verification directly.
Otherwise create spec.md and pending report.md in a dedicated linked worktree,
with scope, dependencies, acceptance, evidence and stop/replan conditions.
Use work --working-tree preflight. Roadmap and issue participation are optional.
No remote call or issue creation is required for planning or pickup.

Use local dev as the execution basis; record the reviewed plan separately.
Criteria change by dated amendment. Inspect actual diff/checkpoint on return,
preserve useful work and identify continuation ownership without guessing
liveness. Manage current priorities without rewriting historical evidence.
